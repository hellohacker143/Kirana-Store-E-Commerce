What a real authentication flow would look like

1
Login request
Browser sends username/email + password to a backend over HTTPS.
2
Credential verification
Server checks a password hash; plaintext passwords should not be stored.
3
Session or access token
Server returns a secure session cookie or an access token, depending on the architecture.
4
Authenticated API request
Subsequent requests carry the session cookie or an authorization token and the server validates it.
5
Logout / expiry
Session is invalidated or token expiry forces re-authentication.

Security checklist for adding auth later

✓ HTTPS only   ✓ password hashing (Argon2id/bcrypt)   ✓ server-side authorization checks   ✓ secure, HttpOnly cookies for sessions   ✓ CSRF protection where applicable   ✓ short-lived access tokens if tokens are used   ✓ never commit secrets to Git
